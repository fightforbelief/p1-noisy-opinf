# p1-noisy-opinf：项目总览与阅读顺序

> 本文件夹里的文档是 `p1-noisy-opinf` 项目的完整实现规格。实现者（Cursor）请按下面的顺序通读全部文档，再开始写代码。

## 1. 项目一句话

**研究带测量噪声的快照数据会让二次 Operator Inference（OpInf）学到的算子产生多大偏差、偏差的结构是什么，以及两种修正估计器（Hermite 矩修正、滞后工具变量）能否消除它。**

研究对象是离散时间二次降阶模型：

$$q_{k+1} = A q_k + H\,s(q_k) + c,$$

其中 $s(q)$ 是 $q$ 的所有二次单项式。观测到的快照带噪声：$\tilde q_k = q_k + \varepsilon_k$。

## 3. 硬性规则（最重要的 10 条）

1. **所有代码都在远程机器 hanqing-win 上运行**，项目目录为 `Desktop\projects\p1-noisy-opinf`。具体见 `06_远程Windows运行手册.md`。
2. **只用 CPU + NumPy/SciPy。** 本项目不需要 PyTorch、GPU、CUDA，**不要安装或升级它们**；按要求检查环境时，只记录现状即可。
3. **所有数据自己生成**（PDE 求解器在 `03` 中有完整规格）。不要下载 PDEBench、The Well 或任何外部数据集。
4. **不要使用其他 P1 仓库**（`p1-temporal-multifidelity-pde`、`p1-efr-opinf-shearflow`、`p1-burgers-opinf`）的代码、数据或结果，也不要修改它们。
5. **公式以 `02_数学与估计器规格.md` 为准。** 如果你认为某个公式有误，**停下来报告**，说明推导理由，不要自行修改实现。
6. **先通过 `05_测试与验证.md` 中的全部测试，再跑正式实验。**
7. **每个报告中的数字都必须来自 `results/` 下的文件**，并由脚本生成。禁止手抄数字，禁止编造或"估计"未运行的结果。
8. 实验失败（发散、数值问题、不收敛）是**结果**，要如实记录，不要通过偷偷调参来消除。
9. 测试轨迹只用于最终评估。所有超参数（只有 ridge 的 λ 需要选）在验证轨迹上选择。
10. **不要写论文正文、摘要或结论性的科学叙述。** 你的交付物是代码、结果文件、图和一份事实性报告（模板见 `08`）。科学解释由项目负责人完成。

## 4. 不需要的东西（明确排除）

- 不需要复杂的流程门控、审批状态机或"冻结协议"文件。保持简单的 git 提交记录和清晰的结果文件即可。
- 不需要神经网络基线（FNO、U-Net 等）。
- 不需要连续时间 OpInf（不需要估计时间导数）。本项目只做**离散时间**映射 $q_k \mapsto q_{k+1}$。
- 不需要实现 Uy et al. (2023) 的 rollout-OpInf 或 Bayesian OpInf。

## 6. 预计时间线（实现者参考）

| 阶段 | 内容 | 预计耗时 |
|---|---|---|
| 1 | 环境检查、仓库骨架、求解器 + 测试（E0） | 1 天 |
| 2 | 特征、估计器、理论公式 + 测试 | 1–2 天 |
| 3 | E1–E2（精确二次系统，有真值） | 1 天 |
| 4 | E3–E5（Burgers POD） | 1–2 天 |
| 5 | E6–E8（第二个 PDE、相关噪声、Δt） | 1–2 天 |
| 6 | 图、报告 | 0.5 天 |

每完成一个阶段，在 `reports/PROGRESS.md` 追加一段汇报（格式见 `07`），然后继续下一阶段。只有遇到 `07` 中列出的"必须停下来问"的情况时才暂停。
